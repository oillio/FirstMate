# Architecture Decision Records (ADRs)

One file for each decision. Use [0000-template.md](0000-template.md). The review process is in [ADR-0010](0010-review-queue-on-github.md).

## Rules

- File name: `NNNN-short-title.md`. Title line: `# ADR-NNNN: Title`. All ADRs stay in this folder.
- Each ADR has one `Status:` line. Values: Proposed, Accepted, Rejected, Deprecated, Superseded by ADR-NNNN. The `Status:` line is the only record of status.
- A proposed ADR is a pull request with the label `type:adr`. The skipper accepts it by merging the pull request that sets `Status: Accepted`.
- Each Proposed ADR has an `Issue: #N` line that links its card on the board.
- Do not edit an Accepted ADR. Write a new ADR and set the old one to "Superseded by ADR-NNNN".
- Give the door type. A one-way door is hard to reverse. It needs more evidence and an independent review.

`tools/check_docs.py` checks these rules in CI.

## What needs review

Open the board column "Needs skipper", or the open pull requests with the label `type:adr`.
